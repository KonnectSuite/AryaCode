# Branding

Two things live here, and they are deliberately separate.

**`arya-wordmark-*.svg`** — the wordmark the application renders: `make-wordmark.cjs` builds both variants from
`wordmark-paths.json`, so a glyph change is a data change, not a redraw.

**`kit/`** — a verbatim copy of the production brand kit (`aryacode-brand-kit`), vendored so the application, the
installer and every document generated by the engineering plugin read the same artwork. `kit/README.md` is the kit's own
documentation; `kit/tools/brand.mjs` is the single source of truth for brand copy, and `npm run check` inside `kit/`
regenerates and validates every asset from it.

## The tokens a surface needs

| Token | Value |
|---|---|
| Name | **AryaCode** — wordmark split `Arya` + `Code`, the trailing word carrying the accent |
| Tagline | *Your AI coding companion* |
| Ink | `#0F141B` · secondary `#171D26` |
| Blue | `#2B6CFF` |
| Cyan | `#00E0D2` |
| Violet | `#8A5CFF` |
| Light | `#E6E8EB` |
| Type | **Sora** for text, **JetBrains Mono** for code |

The logo's frame gradient runs violet → blue → cyan. That gradient is the one accent a document may borrow; the
engineering plugin's report prints it as the rule above its cover and in its footer.

## Using it outside the application

The engineering plugin (`@aryacode/dsh-engineering`) carries the subset a printed page needs under
`packages/l5x/assets/brand/`: the monochrome mark, `Sora-Variable.ttf`, `JetBrainsMono-Variable.ttf` and both OFL
licences. A report embeds them, so a document prints the same on a machine that has never seen this folder.
